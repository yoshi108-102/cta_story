Project Vision

学習者向け深掘りフォーマットを策定するための、
製造現場向け構想整理

熟練者の暗黙知をそのまま直接抽出するのではなく、まず学習者が 自分のわかっていないことを言語化できる状態 をつくる。そこで得られた発話を、効率よく深掘りできる 学習者向けフォーマット として設計し、最終的に再利用可能な seed / working theory へ落とし込む。

このリポジトリの目的は、ACTAをそのまま使うことではなく、学習者向けにアレンジした深掘りフォーマットを策定することである。

1. このリポジトリで本当にやりたいこと

研究開発の目的

普通に会話を深掘りするよりも 効率よく、抜け漏れ少なく深掘りできるフォーマット を設計する。

対象場面

製造現場の新人が、1回の作業後に自分のつまずきや違和感を振り返る 事後振り返り を対象にする。

出力イメージ

単なる要約ではなく、あとで再利用できる seed や working theory へ変換できる記述形式を目指す。

2. なぜ学習者側から始めるのか

問題設定

  • 説明には状況共有が不可欠であり、学習者の理解レベルによって最適な説明は変わる。
  • 学習者は「わからないところがわからない」ため、質問以前の段階で詰まりやすい。
  • 熟練者は教えるコストが高く、詳細説明より実演を選びやすい。
つまり:
熟練者の知識を引き出す前に、学習者が 「何を見て」「どこで止まり」「何を不安に感じ」「何が理解できていないのか」 を最低限共有できる状態をつくる必要がある。

3. 想定する現場

対象領域

製造業。とくに 少量多品種の中小企業 を想定する。

学習者

現場に入ったばかりの 新人。

熟練者

実務を担う 現場のベテラン。

継承の場

リアルタイム指導ではなく、まずは 1回の作業後の事後振り返り を対象にする。

4. ACTAとの関係

一般的な深掘りフォーマットとしては ACTA が有名だが、そのまま使うと今回の状況とは少しずれる。 ACTA は 熟練者を対象に、タスクや認知的要求を引き出す 方向が強い。一方、ここで扱いたいのは 学習者を対象に、わかっていないことを言語化させる フォーマットである。

つまり必要なのは、ACTAの否定ではなく、 「熟練者の知識抽出」から「学習者の困難抽出」へ軸をずらしたアレンジ である。深掘りの入口はタスク分解ではなく、 作業後の困りごと、違和感、不安、判断の迷いから始めるほうが自然である。

5. アレンジ後のフォーマットが担う役割

ACTAとの差分 1

対象者を熟練者ではなく 学習者 に置く。

ACTAとの差分 2

入口をタスク分解ではなく つまずき分解 に置く。

ACTAとの差分 3

出力を cognitive demands table だけでなく、seed / problem / working theory へ接続しやすい記述単位 に寄せる。

6. AIの役割

主導者

AIは補助ではなく、振り返り会話を 主導 する役割を持つ。

学習者への支援
  • 「つまり」の言い換えによる発話の整形
  • 理解確認を通じたメタ認知の促進
  • 困りごとの原因候補や観点の提示
  • 次に熟練者へ聞くべき論点の整理
裏で集めたいもの
  • どの状況で疑問が出たか
  • どの作業で理解が止まりやすいか
  • 新人がどの表現でつまずきを語るか
  • 継承フロー設計に必要な問いのパターン

7. 想定ワークフロー

  1. 新人が1回の作業を終えた直後に、AIとの振り返りを開始する。
  2. AIは「困ったこと」「不安だったこと」「うまくいかなかった感覚」から会話を始める。
  3. 曖昧な発話を受けて、AIが状況・対象物・判断の迷い・試したことを順に掘る。
  4. AIが「つまり」を使って整理し、新人の認識とズレていないか確認する。
  5. 理解不足を論点ごとに分解し、熟練者へ渡せる質問や確認事項の形へ変換する。
  6. 将来的には、その記録を蓄積して、暗黙知抽出のインタビュー設計に還元する。

8. 最終成果物のイメージ

近い概念

今の話で一番近いのは、 学習者の未整理な発話を起点にする seed、 途中の仮説明としての working theory、 そして Knowledge Building の improvable idea という見方。

今回ほしいもの

完成済みの正しい知識単位ではなく、 学習者の雑多な疑念・違和感・アイデアを、改善可能な形で保持する単位 に近い。

記述単位の仮案

たとえば 状況 / 迷い / 見落とした手がかり / 判断 / 不足していた理解 / 熟練者に聞くべきこと のような単位で保持する。

忘れていた概念は、おそらく improvable idea か、 seed / working theory の系列である可能性が高い。

9. この段階での成功条件

短期の成果

新人が感想だけで終わらず、 状況つきの質問 として熟練者に渡せるようになること。

運用上の価値

熟練者がゼロから聞き出さなくても、 短時間で要点にアクセスできる 状態をつくること。

研究・設計上の価値

どの問いが言語化を促すかを蓄積し、 インタビュー構造と成功率の改善 に使えること。

10. 今後さらに詰める論点

  • 深掘りフォーマットの最小項目を何にするか。感想起点で始めるのか、状況起点で始めるのか。
  • 振り返りの最終成果物を、質問リスト・状況整理メモ・理解不足一覧のどれに寄せるか。
  • AIが深掘り質問を行うための領域知識を、作業標準書や過去事例からどう与えるか。
  • 少量多品種でも最初に適用する工程をどこへ絞るか。
  • 言語化支援だけで答え、助言、教育支援まで踏み込むかをどこで線引きするか。
  • 振り返りログを、将来のCTA資源としてどの粒度で構造化するか。
