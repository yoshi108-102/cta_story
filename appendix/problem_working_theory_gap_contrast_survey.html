Focused Survey

Problem / Working Theory / Gap / Contrast をどう切るべきか

結論だけ言うと、Gap/Contrast は文献上ひとつの操作ではない。 gap は「この理論では説明できないこと」の局所診断で、 contrast は「複数の理論や解法を並べたときの差異」の比較活動である。 したがって、両者を1ノードで持つと理論上もUI上も曖昧になりやすい。

対象: Problem → Working Theory → Gap/Contrast 作成日: 2026-03-10 ステータス: 提案サーベイ

1. まず整理

`gap` は何か

現在の working theory が説明できない点、証拠と合わない点、欠けている前提。 Knowledge Building では典型的に This theory cannot explain や need to understand の形で扱われる。

`contrast` は何か

2つ以上の理論、解法、表現、事例を比べて差異を見つけること。 comparison learning や productive failure の文脈では、 差異が構造理解や canonical explanation への準備になる。

要するに、gap は理論の内側にある欠陥で、contrast は理論間にある関係である。

2. この部分に直接効く文献

文献 この論文が扱うもの 読むべきポイント 設計への含意
Muukkonen et al. (1999) problem / working theory / scientific explanation の足場 まず問いと仮説を立て、その後に科学的説明へ進む。 Problem と Working Theory を分ける基礎になる。
Zhang et al. (2007) My theory → This theory cannot explain → A better theory gap は theory-local に記述され、改良理論へ接続される。 Gap は独立ノードにできるが、Contrast とは別だと分かる。
Scardamalia & Bereiter (2006) idea improvement / rise above / authoritative information 理論の比較や改善は、共同体知識を前進させるための活動として置かれる。 Gap の先には evidence と synthesis が必要。
Schwartz & Martin (2004) Inventing to Prepare for Future Learning 不完全な自作解法を複数出し、比較することで後続説明の受け皿ができる。 Contrast は複数案の比較活動として設計すべき。
Star & Rittle-Johnson (2009) solution comparison 複数手法を比べると概念理解と柔軟性が上がる。 Contrast は1つのノートより、比較ビューとして実装した方がよい。
Kapur & Bielaczyc (2012) Productive Failure 失敗解法の生成と比較が、後の統合説明に資する。 Gap と Contrast の後に consolidation が必要。

3. 文献群をつなぐと何が見えるか

1

Problem

何が不明か、どこに説明要求があるかを立てる。

2

Working Theory

いまの仮説や説明を書く。正確さより前進可能性を重視する。

3

Gap / Mismatch

この理論では何が説明できないか、何が欠けているかを見る。

4

Contrast

他の theory や解法と比べ、どこが違うか、何が分岐点かを見る。

5

Evidence

資料、実行結果、教師説明、テスト、観察で理論をふるいにかける。

6

Better Theory

改善された説明や rise-above を作る。

重要な読み替え

文献上、gap は theory refinement の装置で、 contrast は comparison-based learning の装置である。 したがって、 Gap/Contrast を同一ノードに押し込むより、Gap をノード、Contrast をビューまたは操作として扱う方が自然だ。

4. 設計に直結する判断

判断 1

Problem と Working Theory は分ける。

Muukkonen 系の最小骨格。

判断 2

Gap は theory の子として保持する。

Zhang et al. の This theory cannot explain に対応。

判断 3

Contrast は複数 theory の比較ビューとして扱う。

Schwartz / Star / Kapur 系に整合的。

最小構成の提案

最小でも problem、working_theory、mismatch、 evidence、synthesis は持った方がよい。 そして contrast はノード種別でなく、同一 problem 配下の theory を並べて比較する UI に落とす方がきれい。

5. どれから読むべきか

  1. Muukkonen et al. (1999): `problem / working theory / scientific explanation` の原型を見る。
  2. Zhang et al. (2007): `my theory -> this theory cannot explain -> a better theory` の直接形を見る。
  3. Schwartz & Martin (2004): contrast がなぜ learning preparation になるかを見る。
  4. Star & Rittle-Johnson (2009): solution comparison の実証を押さえる。
  5. Kapur & Bielaczyc (2012): failure と comparison を統合した設計原理を見る。
