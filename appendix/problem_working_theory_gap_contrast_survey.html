Focused Survey

Seed / Problem / Working Theory / Gap / Contrast をどう切るべきか

結論だけ言うと、入口は Problem 固定ではない。 文献を束ねると、探究の発火点は少なくとも 問い、アイデア、違和感の3種類ある。 そのうえで、Gap/Contrast は文献上ひとつの操作ではない。 gap は「この理論では説明できないこと」の局所診断で、 contrast は「複数の理論や解法を並べたときの差異」の比較活動である。 したがって、入口も中間操作も、1本鎖で固定するより分岐可能な設計の方が自然だ。

対象: Seed → Problem / Working Theory → Gap / Contrast 作成日: 2026-03-10 ステータス: 提案サーベイ

1. 入口は1つではない

Question Seed

「なんでこうなるの？」という問いから始まる。

Muukkonen 系の inquiry scaffold と相性が良い。

Idea Seed

「こういう仕組みかも」という説明の思いつきから始まる。

Inventing / productive failure 系はこちらが強い。

Anomaly Seed

「ここだけ説明が合わない」という違和感やズレから始まる。

mismatch を先に掴んで theory を立て直す流れ。

ここでの読み替え

Problem は重要だが、常に入口とは限らない。 とくに Idea Seed では、working theory を出したあとで 「そもそもこの理論は何を説明しようとしているのか」を明確化する problematisation が起きる。

なお、gap は理論の内側にある欠陥で、contrast は理論間にある比較関係である。

2. この部分に直接効く文献

文献 この論文が扱うもの 読むべきポイント 設計への含意
Muukkonen et al. (1999) problem / working theory / scientific explanation の足場 問い先行の流れを強く支えるが、working theory を早く出す設計でもある。 Question Seed の原型として読むのが自然。
Zhang et al. (2007) My theory → This theory cannot explain → A better theory theory を先に立て、説明不能点から better theory へ進む流れが見える。 Idea Seed や Anomaly Seed からの改善ループを支える。
Scardamalia & Bereiter (2006) idea improvement / rise above / authoritative information 入口を固定せず、real ideas を共同体知識の改善対象として扱う。 Problem を絶対根にしない設計の理論的支えになる。
Schwartz & Martin (2004) Inventing to Prepare for Future Learning 不完全な自作解法を先に出す。つまり idea-first を明示的に肯定する。 Idea Seed → Working Theory を正当化する中核文献。
Star & Rittle-Johnson (2009) solution comparison 複数手法を比べると概念理解と柔軟性が上がる。 Contrast は1つのノートより、比較ビューとして実装した方がよい。
Kapur & Bielaczyc (2012) Productive Failure 失敗解法の生成と比較が、後の統合説明に資する。 Gap と Contrast の後に consolidation が必要。

3. 文献群をつなぐと何が見えるか

Q

Question Seed の流れ

Seed → Problem → Working Theory → Mismatch → Contrast → Evidence → Better Theory

I

Idea Seed の流れ

Seed → Working Theory → Problematisation → Mismatch → Contrast → Evidence → Better Theory

A

Anomaly Seed の流れ

Seed → Mismatch / Oddity → Working Theory → Problematisation → Contrast → Evidence → Better Theory

重要な読み替え

文献上、入口は単一ではない。Question-first も Idea-first も成り立つ。

文献上、gap は theory refinement の装置で、 contrast は comparison-based learning の装置である。 したがって、 Problem を入口に固定するより、Seed を入口にして Gap をノード、Contrast をビューまたは操作として扱う方が自然だ。

4. 設計に直結する判断

判断 1

入口は Problem ではなく Seed にする。

問い・アイデア・違和感のどれでも始められるようにする。

判断 2

Problem と Working Theory は分ける。

ただし生成順は固定しない。Idea Seed では theory が先でよい。

判断 3

Gap は theory の子、Contrast は比較ビューに分ける。

Zhang 系と Schwartz / Kapur 系を両立できる。

最小構成の提案

最小でも seed、problem、working_theory、 mismatch、evidence、synthesis は持った方がよい。 そして contrast はノード種別でなく、同一 seed から生えた theory を並べて比較する UI に落とす方がきれい。

5. どれから読むべきか

  1. Muukkonen et al. (1999): `problem / working theory / scientific explanation` の原型を見る。
  2. Zhang et al. (2007): `my theory -> this theory cannot explain -> a better theory` の直接形を見る。
  3. Schwartz & Martin (2004): contrast がなぜ learning preparation になるかを見る。
  4. Star & Rittle-Johnson (2009): solution comparison の実証を押さえる。
  5. Kapur & Bielaczyc (2012): failure と comparison を統合した設計原理を見る。
