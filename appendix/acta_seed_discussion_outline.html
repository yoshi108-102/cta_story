ACTA × Seed

Question Seed をどう立ち上げるかを中心にした再整理

以前の整理では、Question Seed をやや早い段階で 「何がわからないか」を言わせる設計として書いていた。 ただ、実際には作業者は最初から自分の不明点を明瞭に言えないことが多い。 ここではその前提を踏まえ、 Seed は探究の発火点であり、problem はその後に明確化される という設計へ寄せて、ACTA や暗黙知抽出系の考え方も含めて再整理する。

Question Seed を worker-facing に再定義 problem は後続で立ち上がる 具体場面からズレを起こす流れを採用

結論の先取り

Question Seed で最初に求めるべきなのは、「どこがわからないか」ではなく、 「どの場面が引っかかるか」「何を予想していたか」「どこで予想が崩れたか」 である。そこから problem を立ち上げ、次に working_theory と evidence へ進む。

Seed

まだ粗い引っかかり、問い、思いつき、違和感の提出。

Problem

この Seed で何を説明したいのかを後から明確化したもの。

Theory / Evidence

どの説明で行くか、何を根拠に確かめるかを次に立てる。

なぜ「どこがわからない？」から始めない方がよいのか

1. メタ認知の前提が高すぎる

作業者は困っていても、その困り方をまだ分解できていないことが多い。 いきなり不明点の自己診断を求めると、空振りか一般論になりやすい。

2. 身体的・状況的な違和感は言語化前に現れる

とくに技能学習や現場判断では、 「何か違う」「ここで止まる」「この感じが変だ」が先に来る。 不明点はその後で言葉になる。

3. 抽象質問は文脈を失いやすい

具体場面を離れると、手がかり、順序、期待、比較対象が消えやすい。 その結果、問いが深まる前に平板な説明へ閉じてしまう。

したがって、Question Seed は 完成した質問文を回収するノードではなく、再訪したい一場面を提出するノード と読む方が自然である。

理論的に見ると、問いはどう立ち上がるか

Progressive Inquiry

Seed が先、problem は後

このプロダクトの設計書でも、 seed は探究の発火点、 problem は「この seed で何を説明したいのか」の明確化とされている。

つまり、問いは最初から完成している前提ではない。

ACTA / CTA

一般論ではなく、難しい局面へ戻す

ACTA はまずタスクの中の難所に当たりを付け、 その後に具体例ベースで手がかり、判断、初心者の失敗を掘る。 先に詳細な自己説明を求める設計ではない。

Cognitive Apprenticeship

見える化してから articulation へ行く

認知的徒弟制では、まず expert thinking を visible にし、 modeling, coaching, scaffolding を通じてから articulation や reflection へ進む。

Decoding / Bottleneck

先に bottleneck を見つける

学習者の詰まりを先に捉え、 そのあとで専門家側の見えない操作を外化する流れが強い。 問いは、詰まりの指摘から生成される。

複数理論を横断すると、 問いの洗い出しは「内省で回収する」より「具体場面を再生し、期待と実際のズレを外化してから命名する」方が筋がよい と言える。

Question Seed の推奨フロー

Question Seed では、最初から完成した疑問を書かせるのではなく、 次のように一段ずつ立ち上げる。

1

場面を選ぶ

まず、作業者が「もう一度見たい」「ここで止まりたい」と感じる 具体的な一場面を選ぶ。

ここではまだ質問文にしなくてよい。

2

予想を出す

その場面で何が起きると思っていたか、 何を見るつもりだったか、どう進むと予期していたかを出す。

3

実際とのズレを出す

予想と実際の差、止まった瞬間、気になった挙動、 違和感のある箇所を外化する。

4

problem を立てる

そのズレから、 「つまりこの Seed で何を説明したいのか」を絞り込んで problem にする。

5

working theory と evidence に進む

ここで初めて仮説を立て、 何を比較し、どんな根拠を取りに行くかを設計する。

Question Seed で最初に投げるとよい問いの型

よい入口

  • どの場面をもう一度見たいか
  • そこで何が起きると思っていたか
  • 実際にはどこで予想が崩れたか
  • どの瞬間を止めて見たいか
  • 何を比べると分かりそうか

早すぎる入口

  • 何がわからないのか説明してください
  • この現象の原因は何ですか
  • 正しい説明を書いてください
  • どの知識が足りないですか
  • 問題点を一般化してください

重要なのは、Question Seed は答えを言わせる prompt ではなく、 注意を向け直させる prompt であることだ。

React Flow でまとめるなら

いまの話をそのまま React Flow に載せるなら、 Question Seed から 3 本に分けるのがよい。 ただし本当に重要なのは、 3 本の下にぶら下がる深掘り観点がかなり共通だという点である。

1

Question Seed

再訪したい場面、止まった瞬間、気になる挙動を置く。

2

3 本の深掘り枝

Situation, Expectation, Actual の 3 枝に分けて、それぞれを同じ観点で掘る。

3

Mismatch

Expectation と Actual の差、および Situation の見落としを 差分としてまとめる。

4

Problem

その差分のうち、何を説明対象にするかを絞る。

5

Working Theory / Evidence

そこから仮説と検証へ進む。

ポイントは、Situation / Expectation / Actual は別々の意味を持つが、 その中で見る観点はかなり共通であることだ。

共通プローブ軸として持つとよさそうなもの

「どういう処理の時だったか」「丸棒の材料は何だったか」のような深掘りは、 branch ごとに別々の質問群を持つより、 共通プローブ軸として持った方が整理しやすい。

共通プローブ軸 見るもの 例
工程 / タイミング どの処理、どの局面、どの順番だったか どの工程で止まったか、切り返し前か後か
対象 / 材料 何に対して作業していたか、その対象の性質は何か 丸棒の材質、太さ、状態、個体差
道具 / 機械 / 介在物 何を使っていたか、どの設定・接触条件だったか 治具、機械設定、刃、補助具
身体 / 操作 どんな姿勢、力加減、手順、身体感覚だったか 押し方、力の入り方、手の位置、抵抗感
環境 / 制約 周囲条件や制約は何だったか 時間制約、視界、温度、周囲の邪魔、騒音
判断基準 / 良否の見立て 何をもって良い・危ない・次へ進めると見ていたか どの見え方なら OK と思っていたか

この軸は Question Seed 専用というより、 Situation / Expectation / Actual の 3 枝すべてに共通して適用するための深掘りレンズ として使うのがよい。

React Flow 上のまとめ方の勘所

保存するノード

  • Question Seed
  • Situation
  • Expectation
  • Actual
  • Mismatch
  • Problem
  • Working Theory
  • Evidence

別 node kind にしない方がよさそうなもの

  • 工程 / 材料 / 身体 / 環境などの共通プローブ軸
  • それぞれの軸に対する質問テンプレ
  • 入力補助のための小さな確認項目

共通プローブ軸まで node kind にすると、 スキーマが task 依存の用語で膨らみやすい。 React Flow では 枝の中の補助 UI / node 内の structured note / side panel のテンプレ として持つ方がきれいである。

Seed 別に何を話すか

Question Seed

引っかかりから問いを立ち上げる

作業者に、再訪したい場面と予想のズレを出させる入口。

  • 1. どの場面を problem 化したいかを見つける

    まずは「何がわからないか」ではなく、 「どこで止まるか」「どこを見直したいか」を出す。

  • 2. 予想と実際の差を外化する

    何を期待していたか、何が違っていたかを通じて、 問いの輪郭を少しずつ作る。

  • 3. そこから problem と theory へつなぐ

    引っかかりを説明対象に変え、 後続の working_theory と evidence を立てられるようにする。

Idea Seed

思いついた説明の筋を立てる

「こういう仕組みかも」という仮の見立てから始める入口。

  • 1. このアイデアは何を説明したいのかを定める

    仮説の射程を定め、 どの現象・どの判断・どの変化に効く説明なのかを明確にする。

  • 2. 正しいなら何が観察されるはずかを出す

    予測される手がかり、見え方、段取りの違いを立て、 theory を観察可能な形にする。

  • 3. 崩れる境界を探す

    例外条件や通用しない場面を探し、 mismatch や比較へ接続する。

Anomaly Seed

ズレから立て直しを始める

「ここだけおかしい」「説明が合わない」から始まる入口。

  • 1. 何が典型から外れていたかを掴む

    単なる失敗ではなく、 何が通常パターンと違っていたのかを丁寧に言語化する。

  • 2. そのズレをどう検知したかを出す

    小さな兆候、比較対象、身体感覚、早期発見の手がかりを拾う。

  • 3. 検知後の立て直し方を整理する

    原因の切り分け、優先順位、再判断の手順を整理し、 theory の更新へつなぐ。

ノード設計に落とすと

段階 ここでやること まだ求めないこと 次に進むノード
Question Seed 再訪したい場面、予想、ズレ、気になる箇所を出す 完成した原因説明や自己診断 problem
Problem この Seed で何を説明したいのかを明確にする 唯一の正解 working_theory
Working Theory 現時点の説明を立てる 十分な確証があること mismatch, evidence
Anomaly Seed 典型から外れた箇所を先に出す 最初から一般法則にまとめること working_theory, problem
